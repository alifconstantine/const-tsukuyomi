# Rancangan kompatibilitas aplikasi Windows dan Android

Status 8 November 2026 · Riset dokumentasi upstream dan audit jalur pemasangan pada `3da2617d2`. Implementasi dan penerimaan runtime masih terbuka. Urutan pekerjaan ada di [roadmap](../implementation_plan.md#fase-07b--kompatibilitas-aplikasi-windows-dan-android).

## Pengalaman pengguna yang dituju

Setelah memasang ConstOS, pengguna membuka installer `.exe` atau `.msi` dari Thunar, mengonfirmasi file yang akan dijalankan, menyelesaikan wizard aplikasi, lalu memilih **Jalankan** atau membuka aplikasi dari Wofi. Untuk program portabel, pengguna memilih **Jalankan** tanpa wizard pemasangan. ConstOS menyediakan Wine dan menyiapkan lingkungan pengguna secara otomatis. Pemasangan aplikasi lokal yang masuk daftar dukungan dapat dilakukan dengan jaringan terputus setelah instalasi ConstOS. Installer aplikasi yang mengunduh isinya sendiri tetap membutuhkan jaringan.

Android menyusul sebagai fitur opsional pada sistem terpasang. Pengguna yang memilih dukungan Android saat memasang ConstOS dapat memilih **Pasang APK** di Thunar, lalu membuka aplikasi dari Wofi. Target awalnya APK tunggal yang kompatibel dengan x86_64. Keduanya memakai sesi desktop Hyprland yang sama dan dapat berjalan tanpa Harness atau akun AI.

## Windows dengan Wine

### Paket dan runtime

1. Pilih paket stabil `wine` dari repositori target yang dipercaya. Saat implementasi, periksa paket dan versi yang benar-benar dipilih pacman melalui [konfigurasi target](../installer/pacman.conf) dan rekam hasilnya. Tambahkan dependensi runtime ke manifest target dan metadata paket pemilik sesuai pemakaian. Arch mendokumentasikan WoW64 baru untuk aplikasi Windows 32-bit dalam prefix 64-bit. Uji x86 dan x64 sebagai dua skenario terpisah. [Paket Wine Arch](https://archlinux.org/packages/extra/x86_64/wine/) · [Transisi WoW64 Arch](https://archlinux.org/news/transition-to-the-new-wow64-wine-and-wine-staging/)
2. Uji `wine-mono` dan `wine-gecko` yang sesuai dengan Wine terpilih. Sertakan komponen yang diperlukan agar inisialisasi dan aplikasi dalam cakupan awal tidak menampilkan dialog unduh. Periksa pula audio dan dependensi opsional sesuai aplikasi yang masuk matriks. [Dependensi paket Wine](https://archlinux.org/packages/extra/x86_64/wine/#pkgdeps) · [Panduan paket Wine Arch](https://wiki.archlinux.org/title/Wine_package_guidelines)
3. Mulai dari driver grafis default Wine di Hyprland, dengan XWayland tersedia. Catat driver yang benar-benar dipakai oleh setiap kasus uji. Permainan Steam lewat Proton, DXVK tambahan, aplikasi yang bergantung pada driver Windows, dan anti-cheat merupakan cakupan terpisah. [Dokumentasi Proton Valve](https://partner.steamgames.com/doc/steamhardware/proton)

### Buka file, pasang, dan jalankan

1. Sediakan Desktop Entry untuk membuka satu file lokal (`Exec` dengan `%f`, `Terminal=false`) melalui handler ConstOS. Ambil MIME aktual dari basis data paket target menggunakan `xdg-mime query filetype` pada installer MSI, EXE, dan contoh file yang salah tipe. Uji klik ganda serta **Buka Dengan** di Thunar. Periksa `wine.desktop` dari paket Arch dan asosiasi yang dibuat Wine agar default vendor membuka dialog konfirmasi ConstOS, termasuk pada akun baru. Pertahankan pilihan asosiasi yang ditetapkan pengguna. [Desktop Entry Specification](https://specifications.freedesktop.org/desktop-entry/latest-single/) · [MIME Applications Associations](https://specifications.freedesktop.org/mime-apps/latest-single/) · [Daftar file paket Wine](https://archlinux.org/packages/extra/x86_64/wine/files/)
2. Tampilkan nama dan lokasi file, aksi, serta **Batal** sebelum eksekusi. Untuk `.exe`, sediakan pilihan **Pasang** dan **Jalankan portabel** karena ekstensi itu juga dipakai program yang langsung berjalan. Terima file reguler lokal yang dipilih, validasi format yang diterima runner, dan teruskan path absolut sebagai satu argumen proses. Hindari interpolasi ke shell, eksekusi saat unduhan selesai, dan elevasi untuk installer aplikasi.
3. Buat satu `WINEPREFIX` untuk setiap aplikasi yang dikelola, di bawah `$XDG_DATA_HOME/constos/windows/` dengan fallback XDG biasa. Inisialisasi secara lazy dalam sesi pengguna melalui `wineboot --init`. Jalankan `wine` dengan EXE yang dipilih atau `msiexec /i` dengan MSI, memakai prefix yang sama. Verifikasi penerjemahan path MSI oleh build Wine terpilih, termasuk spasi dan Unicode. Kunci pekerjaan per prefix agar klik ulang tidak membuat dua instalasi. Simpan status dan log diagnostik terbatas di `$XDG_STATE_HOME`, dengan pilihan coba ulang setelah kegagalan. Prefix memisahkan registry dan dependensi aplikasi. Wine tetap memiliki akses berkas yang tersedia bagi akun pengguna. [`wine(1)`](https://man.archlinux.org/man/wine.1.en) · [`wineboot(1)`](https://man.archlinux.org/man/wineboot.1.en) · [`msiexec(1)`](https://man.archlinux.org/man/msiexec.1.en)
4. Gunakan shortcut Start Menu yang dihasilkan installer sebagai kandidat program utama. Uji hasil `winemenubuilder` dengan Wine terpilih dan cara menahan atau menyaring ekspor selama setup agar launcher tidak menampilkan shortcut ganda atau belum valid. Untuk integrasi terkelola, publikasi hanya shortcut milik ConstOS yang menunjuk ke ID aplikasi dan prefix terkait, dengan target yang sudah diverifikasi ada. Apabila kandidat ambigu atau tidak ada, biarkan pengguna memilih program yang benar lewat UI. Tawarkan **Jalankan** ketika target valid. Exit code proses saja tidak cukup karena beberapa installer meluncurkan proses anak, selesai tanpa shortcut, atau membatalkan pemasangan. [Sumber `winemenubuilder`](https://github.com/wine-mirror/wine/blob/master/programs/winemenubuilder/winemenubuilder.c)
5. Pertahankan prefix dan shortcut setelah login ulang, reboot, serta upgrade paket. Upgrade ConstOS tidak mengambil alih prefix Wine yang sudah dibuat pengguna di luar fitur ini. Untuk aplikasi terkelola, pisahkan tindakan menghapus shortcut dari tindakan menghapus prefix beserta datanya. Catat dampak rollback paket terhadap prefix karena `@home` berada di luar snapshot root.

## Android dengan Waydroid

1. Tambahkan pilihan Android sebelum preflight installer. Verifikasi sumber paket Waydroid beserta dependensi LXC terhadap repositori target. Jika perlu paket ConstOS sendiri, bangun dari sumber terpin dalam jalur build tepercaya dan sertakan artefak serta metadata verifikasinya sebelum partisi. Bandingkan hasil dengan dukungan Binder pada kernel CachyOS BORE yang benar-benar terpasang, termasuk node binder, vndbinder, dan hwbinder serta jalur memfd. [Kernel CachyOS](https://wiki.cachyos.org/features/kernel/#miscellaneous) · [Probe driver Waydroid](https://github.com/waydroid/waydroid/blob/main/tools/helpers/drivers.py)
2. Sediakan satu pasangan `system.img` dan `vendor.img` x86_64 yang cocok, mulai dari varian tanpa GApps. Unduh dan verifikasi pasangan sebelum partisi pada pemasangan online, lalu stage ke target. Catat asal, versi, hash, ukuran, dan hak redistribusi sebelum menyertakan image di ISO atau repo paket. Penggunaan pertama dengan jaringan terputus mensyaratkan image sudah tersedia di target. Installer ConstOS saat ini tetap menggunakan jalur online. [Image Waydroid lokal](https://docs.waydro.id/faq/using-custom-waydroid-images) · [Validasi unduhan Waydroid](https://github.com/waydroid/waydroid/blob/main/tools/helpers/images.py)
3. Untuk jalur image yang sudah disediakan vendor, uji penempatan keduanya di `/usr/share/waydroid-extra/images/`. Upstream mendeteksi pasangan tersebut dan melewati unduhan OTA. Jika jalur ini dipakai, tetapkan pembaruan pasangan melalui rilis paket ConstOS karena updater bawaan Waydroid dinonaktifkan pada mode itu. Uji migrasi data dan recovery untuk pasangan yang baru. Jalankan `waydroid init` melalui provisioning sistem di boot target yang sudah memakai kernel target, sebelum container digunakan. Gunakan pemeriksaan state dan versi untuk retry, dan hindari pemaksaan `--force` setiap boot. [Initializer Waydroid](https://github.com/waydroid/waydroid/blob/main/tools/actions/initializer.py) · [Konfigurasi dan lokasi image](https://github.com/waydroid/waydroid/blob/main/tools/config/__init__.py) · [Kebijakan updater image lokal](https://github.com/waydroid/waydroid/blob/main/tools/helpers/lxc.py)
4. Pakai `waydroid-container.service` sebagai pemilik container sistem pada target yang memilih fitur. Mulai sesi Waydroid sebagai pengguna grafis dengan environment Wayland aktual dan tunggu Android siap sebelum memasang APK. Aktifkan `persist.waydroid.multi_windows` dan restart sesi sesuai prosedur upstream. Uji logout/login ulang dan perilaku dua akun secara terpisah karena layanan container berada pada lingkup sistem. Kegagalan provisioning tetap harus memungkinkan login Hyprland. [Unit systemd Waydroid](https://github.com/waydroid/waydroid/blob/main/systemd/waydroid-container.service) · [Mode multi-window](https://docs.waydro.id/usage/install-on-desktops#launch-waydroid-in-multi-window-mode)
5. Jalankan `waydroid app install` untuk file yang dikonfirmasi. Serialkan pemasangan karena upstream memakai nama staging `base.apk` yang sama. Pastikan package ID dan versi terpasang dari hasil backend sebelum melaporkan sukses. Implementasi upstream yang ditinjau mencatat beberapa error ke log dan tidak meneruskan hasil `installApp` melalui exit code; pembaruan APK dengan ID sama juga perlu verifikasi versi. Gunakan entri launcher yang diekspor Waydroid, dan uji `waydroid app launch <package>` bila perlu mendiagnosis. [Alur pemasangan APK](https://docs.waydro.id/usage/install-and-run-android-applications) · [Sumber app manager](https://github.com/waydroid/waydroid/blob/main/tools/actions/app_manager.py)

Cakupan pertama menunda GApps/Play Store, translasi APK khusus ARM, APK split, dan klaim dukungan akselerasi GPU tertentu. Uji DNS dan jaringan container dengan kebijakan firewall yang berlaku. Gunakan software rendering hanya sebagai profil VM atau fallback yang dicatat tersendiri, lalu uji akselerasi pada perangkat fisik sebelum mendukung kombinasi GPU/driver tersebut. [Jaringan Waydroid](https://docs.waydro.id/debugging/networking-issues) · [Grafis Waydroid di VM](https://docs.waydro.id/faq/get-waydroid-to-work-through-a-vm)

## Skenario penerimaan

Gunakan [panduan pengujian terpadu](acceptance-guide.md#installer-dan-reboot-tanpa-iso) pada disk VM uji yang sudah dikonfirmasi. Untuk masing-masing skenario, mulai dari instalasi bersih atau snapshot bersih yang dicatat. Catat SHA, checksum ISO, versi kernel dan paket, asal/hash installer aplikasi, profil VM atau GPU/driver, kondisi jaringan, hasil aktual, serta lokasi bukti yang sudah diperiksa privasinya.

| Skenario | Bukti yang diperlukan |
| --- | --- |
| Instalasi bersih | Pilih cakupan kompatibilitas, selesaikan Calamares, lalu reboot tanpa ISO dan login dengan akun baru. Cocokkan `pacman -Q` dengan transaksi preflight, cek ukuran unduhan/cache dan ruang disk, serta pastikan paket/izin khusus live tidak diwariskan. |
| Windows x64 dan x86 | Dengan jaringan terputus setelah memasang ConstOS, buka MSI x64 dan EXE x86 dari Thunar dalam prefix terpisah. Sebagai kandidat, gunakan MSI x64 dan EXE x86 dari [unduhan resmi 7-Zip](https://www.7-zip.org/download.html). Selesaikan wizard, buka program langsung dan dari Wofi, buat serta buka arsip uji. Setelah reboot, buka lagi tanpa mengulang setup atau unduhan runtime. |
| Windows portabel dan pembatalan | Jalankan EXE portabel dari [rilis resmi SumatraPDF](https://www.sumatrapdfreader.org/download-free-pdf-viewer) sebagai kandidat. Uji file dengan nama berisi spasi/Unicode, format salah, pembatalan konfirmasi dan wizard, serta percobaan ulang. Periksa fokus dan navigasi keyboard, ketiadaan shortcut sukses palsu, dan tidak ada proses kedua untuk prefix yang sama. |
| Pembaruan dan akun Windows | Jalankan update penuh, reboot, lalu buka aplikasi dari prefix semula. Pastikan default vendor tetap meminta konfirmasi dan akun kedua tidak mendapat akses ke data prefix akun pertama. Uji upgrade akun yang telah punya pilihan MIME sendiri. |
| Android dan kegagalan | Dengan runtime dan image yang sudah disiapkan installer, putus jaringan sebelum login pertama. Pasang APK x86_64 yang telah dicatat sumber, versi, dan hash-nya. Buka jendela terpisah dari Wofi, uji mouse, keyboard, resize, dan penyimpanan data setelah reboot. Uji APK ARM-only atau rusak, kegagalan image/layanan, dan coba ulang. Status UI harus mengikuti hasil, desktop Linux tetap bisa dipakai. |

Riset ini mendokumentasikan jalur integrasi serta pengujian yang perlu dijalankan. Dukungan publik mengikuti daftar aplikasi, versi, dan perangkat yang benar-benar lulus.
