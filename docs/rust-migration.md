# Rencana migrasi Rust ConstOS

Migrasi dimulai dari runtime milik ConstOS. Setiap cutover memiliki gerbang sendiri supaya kegagalan wizard, backend, dan desktop bisa dilacak ke perubahan yang diuji. Build Rust memakai workspace dan `Cargo.lock` yang sama. Status dan bukti per build dicatat di [roadmap](../implementation_plan.md#fase-08--system-monitor-doctor-dan-widget).

| Urutan | Sumber dan perubahan | Gerbang |
| --- | --- | --- |
| 1. Telemetri | `crates/constd` memakai collector Rust yang sama dengan CLI. Paket core memasang daemon dan aktivasi D-Bus. Staging live mengambil berkas dari paket yang sama. | Aktivasi dan snapshot sebagai akun biasa pada Diagnostics live dan target terpasang. Cocokkan RAM dan versi kernel dengan sumber sistem. [Kontrak D-Bus](architecture.md#telemetri-sesi) |
| 2. Backend installer | Port [`backend.py`](../installer/scripts/backend.py) dalam satu binary khusus live. Awali dari parsing rencana, daftar disk, dan preflight baca-saja dengan fixture. Port operasi tulis setelah hasilnya setara. Pertahankan `--list-disks`, identitas disk dan batas payload, JSON stdin, event `@@CONST_STEP`, kode keluar, serta pemanggilan utilitas sistem dengan argumen terpisah. Ganti jalur executable di TUI dan staging setelah uji perilaku. | Disk kosong UEFI terpasang sampai login tanpa ISO. Disk berubah dan arsip rusak ditolak. Putus jaringan saat preflight menghasilkan nol tulis. Periksa kegagalan sesudah storage, unmount, browser, akun, Snapper, dan log privat. [Penerimaan installer](acceptance-guide.md#installer-dan-reboot-tanpa-iso) |
| 3. Probe di VM | Jika targetnya menghapus runtime Python dari ISO, port [`guest_probe.py`](../tests/live/guest_probe.py) atau sediakan probe Diagnostics Rust. Pertahankan batas waktu, data yang dilaporkan, dan redaksi. Runner Python di host bisa mengirim binary x86_64 yang dapat berjalan di guest dan memeriksa checksum serta hasilnya. | Kedua entri GRUB lulus, termasuk Diagnostics dan aktivasi `constd`. Periksa hasil resolusi dependensi manifest sebelum mencabut `python` atau `python-pip` dan ukur perubahan ukuran ISO. [Smoke live](build-guide.md#pemeriksaan-dan-artefak) |
| 4. TUI Go | Jika standardisasi toolchain dipilih, port [wizard Go](../installer/tui), modul terjemahan, dan data pilihan yang dipakai alur ConstOS. Evaluasi Ratatui dengan backend terminal yang mendukung resize dan input keyboard. Pertahankan `constos-tui --version`, protokol backend, file serah-terima keyboard ke Cage, serta atribusi Ryoku. Ganti builder dan CI setelah cutover. | Uji layar sempit, posisi kartu, filter dan keyboard, cancel, progres, Retry sebelum storage, Finish, dan login. Bandingkan ukuran binary, waktu buka, dan RAM pada build yang setara sebelum mengklaim penghematan. |
| 5. Welcome dan katalog | Port supervisor [`guide.py`](../desktop/welcome/guide.py) jika perlu menyatukan runtime. Pertahankan QML, path marker, lock per sesi, dan penandaan setelah penutupan normal. Saat mengerjakan Const Store, pindahkan [backend katalog](../desktop/welcome/catalog.py) ke Rust agar inventaris dan transaksi berbagi kontrak scope, origin, dan ref. Evaluasi ulang [UI GTK](../desktop/welcome/welcome.py) ketika Store punya UI penerus. | Login pertama dan buka ulang manual bekerja pada target baru serta akun lama. Uji remote GPG, instalasi per akun, aplikasi system-wide, kegagalan jaringan, retry, dan konfirmasi ref yang benar. Periksa dependensi transitive paket target sebelum menghapus `python-gobject` dari manifest. |

Tes host, ekspor aset, dan skrip pengemasan bisa tetap memakai Python atau Bash selama alurnya sesuai kebutuhan build. Dux Shell dan yay mengikuti paket upstream. Helper computer use Rust tetap mengikuti gerbang izin dan kemampuan Wayland di [fase 12](../implementation_plan.md#fase-12--native-computer-use-observasi-lokal).
